orquestrador multi-agente · multi-provedor

Várias chaves de API — Gemini, OpenAI (ChatGPT), Anthropic (Claude) e xAI (Grok) — trabalhando juntas: uma planeja, várias escrevem o arquivo em seções, uma ou mais revisam e corrigem, e no final tudo é unido em um único arquivo pronto para baixar.

01 · Chaves de API — adicione uma ou mais, de qualquer provedor

As chaves ficam apenas na memória desta aba (não são salvas) e cada uma é chamada diretamente do seu navegador na API do provedor escolhido (Gemini, OpenAI, Anthropic ou xAI/Grok). Misturar provedores ajuda a otimizar o uso de tokens: o orquestrador distribui as chamadas entre todas as chaves disponíveis (round-robin), então quanto mais chaves/provedores diferentes você adicionar, mais o trabalho roda em paralelo e menos cada conta individual é sobrecarregada — além de servir como fallback automático (se uma chave falhar ou ficar sem cota, o pipeline segue com as outras). Cada chave tem um papel: "geração + verificação" entra no rodízio dos dois tipos de tarefa; "só geração" nunca é chamada para revisar; "só verificação" fica reservada para revisar/corrigir e não escreve seções — útil para dedicar uma chave inteira a manter a qualidade do arquivo enquanto as outras produzem código. O arquivo cresce seção por seção até chegar perto da meta de linhas (sem ficar propondo seções novas depois disso), e a verificação final roda uma única vez, básica, só para pegar erros que realmente quebram o código — não fica revisando e corrigindo em loop. Trate suas chaves como senhas.

Nota sobre CORS: a API da OpenAI (e às vezes a da xAI) pode bloquear chamadas feitas diretamente do navegador por política de CORS, retornando erro de rede antes mesmo de chegar ao seu servidor. Se isso acontecer com uma chave OpenAI/xAI, o agente será marcado como "falha" e o orquestrador continua com as demais chaves. A Google (Gemini) e a Anthropic (com o cabeçalho de acesso direto do navegador) normalmente funcionam sem esse problema.
